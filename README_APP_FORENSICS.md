=========================================================

Purpose
-------

What is application forensics?
-----------------------------
Application forensics is the practice of collecting, analyzing, and interpreting data produced by software applications to investigate incidents, support incident response, or provide evidence in legal proceedings. It focuses on artifacts generated by applications (logs, configuration files, archives, caches, temporary files, and metadata) and the ways these artifacts show application behavior, user actions, and data provenance.

Core goals of application forensics
----------------------------------
- Evidence identification: locate application artifacts relevant to an investigation.
- Evidence preservation: capture artifacts in a manner that prevents tampering and preserves integrity.
- Evidence analysis: interpret artifact contents, metadata, and relationships to reconstruct events.
- Reporting and validation: produce reproducible results (hashes, logs) and document processes for chain-of-custody.

Why application forensics matters
---------------------------------
- Applications are the primary source of user activity and data; they often retain copies, logs, or metadata that are crucial to an investigation.
- Many artifacts are transient (temporary files, caches), so timely and methodical collection is essential.
- Proper preservation (hashing, logging, controlled extraction) is necessary for evidence admissibility and to defend findings in academic or legal review.

How `7zip_app` maps to application-forensics concepts
---------------------------------------------------
This project is a small, controlled demonstration of concepts that are central to application forensics. Below, each project element is mapped to a forensic goal and an explanation you can present to your professor.

1) Artifact creation and packaging — `demo_compress/compress.bat`
- Forensic mapping: Simulates collection and packaging of evidence (e.g., compressing files from a suspect system into an evidence archive).
- Key teaching points:
  - Packaging preserves a snapshot of files at collection time.
  - Use of header encryption (`-mhe=on`) shows how packaging options change visibility of metadata; encrypted headers conceal filenames and timestamps.
  - Discuss reasons to package (space, transport, confidentiality) versus reasons not to (added complexity for analysis).

2) Metadata inspection — `demo_list/list_contents.bat`
- Forensic mapping: Demonstrates how an investigator inspects archive metadata without full extraction.
- Key teaching points:
  - Understanding file sizes, timestamps, and names can guide triage and prioritize analysis.
  - Show difference in what is visible when header encryption is used.

3) Integrity verification — `demo_hash/hash.bat`
- Forensic mapping: Shows hashing workflow for chain-of-custody and evidence validation.
- Key teaching points:
  - Hash an archive immediately after collection and before any handling (record value in notes/logs).
  - Recompute later to show evidence hasn't changed.
  - Explain SHA-256 selection (collision resistance, common practice) and limitations (hash collision theoretical risk vs practical reliability).

4) Controlled extraction — `demo_extract/extract.bat`
- Forensic mapping: Demonstrates safe extraction practices and maintaining an auditable trail.
- Key teaching points:
  - Always extract into a new, dedicated directory to avoid contaminating evidence.
  - After extraction, compute hashes of extracted files and compare with recorded values if available.
  - Discuss read-only mounts, forensic image extraction, and why live modifications must be avoided.

5) Searching and triage — `demo_search/search_by_name.bat`
- Forensic mapping: Demonstrates triage methods — searching for likely keywords or filenames across archives.
- Key teaching points:
  - Show how `7z l` combined with text search is a quick triage method.
  - Explain failed searches when header encryption is present, and discuss alternative approaches (obtaining password, memory analysis, metadata from other artifacts).

Evidence lifecycle in the demo
------------------------------
The project simulates a simple evidence lifecycle you can explain step-by-step:
1. Collection: files in `demo_compress/sample_files` represent raw artifacts.
2. Preservation: `demo_compress/compress.bat` packages artifacts into `sample.7z` (optionally encrypted).
3. Verification: `demo_hash/hash.bat` creates a SHA-256 digest of the archive; record this in an evidence log.
4. Triage: `demo_list/list_contents.bat` and `demo_search/search_by_name.bat` help prioritize what to inspect.
5. Recovery: `demo_extract/extract.bat` extracts files for detailed analysis; verify extracted contents against recorded hashes.
6. Reporting: produce a short report or log of commands, outputs, and recorded hashes for reproducibility.

How to present this project to your professor (script)
-----------------------------------------------------
- Start with a 1-2 minute statement: define application forensics and state the demo's learning goals (collection, preservation, verification, analysis).
- Walk through the Evidence lifecycle above, running each script and explaining the purpose and expected output.
- Emphasize reproducibility: show `run_all_demos.bat` runs the exact same steps.
- Demonstrate a variation: toggle header encryption in `compress.bat` and re-run the list/search steps to show how encryption changes analysis.
- Conclude by summarizing trade-offs (privacy vs analyzability) and next steps for a full forensic workflow (imaging, preserving logs, cross-correlation with system artifacts).
